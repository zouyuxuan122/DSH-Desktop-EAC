# Repository Guidelines

## Scope

This repository contains the Electron desktop wrapper in `dsh-desktop/` plus
optional plugins and research material. The desktop application supports
Windows x64 and Linux x86_64 (Arch / Ubuntu / Debian / Fedora via
pacman / deb / rpm / AppImage). Keep platform-specific behavior isolated
behind `process.platform` checks and preserve all targets when changing shared
startup, updater, tray, notification, or process-lifecycle code.

## Working Directory

Run desktop commands from `dsh-desktop/`:

```bash
npm install
npm run fetch-runtime
npm test
```

Build targets:

```bash
npm run dist          # Windows portable + NSIS
npm run dist:arch     # Arch Linux x86_64 pacman package
npm run dist:deb      # Ubuntu / Debian x86_64 .deb package
npm run dist:rpm      # Fedora x86_64 .rpm package
npm run dist:appimage # distro-agnostic x86_64 AppImage
npm run dist:linux    # All configured Linux targets
```

Generated packages are written to `dsh-desktop/dist/`. The `vendor/` directory
is generated by `fetch-runtime` and contains the platform-specific bundled Node
runtime and npm CLI.

## Cross-Platform Constraints

- The application runs dsh with the bundled plain Node runtime, not Electron's
  embedded Node. Keep `asar: false`, `npmRebuild: false`, and
  `buildDependenciesFromSource: false`.
- Resolve the bundled executable by platform: `node.exe` on Windows and `node`
  on Linux.
- Windows process-tree cleanup uses `taskkill`; Linux cleanup uses process
  groups and signals. Do not introduce shell commands that assume only one OS.
- Windows portable/NSIS self-update behavior is not automatically suitable for
  Linux package installations. Linux package upgrades should remain owned by
  each distribution's package manager (pacman / apt / dnf) or AppImage
  replacement.
- Paths, environment variables, config directories, and executable permissions
  must be tested on both Windows and Linux.

## Native Runtime Payloads

The package contains native dependencies such as `node-pty`, Sharp, Koffi,
Jieba, and sqlite-vec. The bundled `dsh-tdai-memory` plugin also relies on
checked-in JavaScript `dist/` output and platform-native binaries.

`scripts/after-pack.js` restores plugin and npm trees that electron-builder may
otherwise prune, then audits required runtime files. Do not remove apparently
generated plugin `dist/` directories or Linux native packages without proving
that the packed application still imports and exercises them successfully.

For Arch Linux x86_64, required memory-plugin payloads include:

- `@node-rs/jieba-linux-x64-gnu`
- `sqlite-vec-linux-x64/vec0.so`

### Linux support window and glibc baseline

The official Linux support window is **distributions released between
2025-01-01 and 2026-08-15** (see `docs/support-matrix.md` for the per-distro
table). Every bundled native payload must keep its maximum referenced glibc
symbol at or below `GLIBC_2.34` — the empirical floor of a Debian 12 build —
so the whole window (glibc 2.41+) plus still-maintained older LTS releases
work from one artifact.

`node-pty`'s `pty.node` is the only payload compiled at install time
(node-pty@1.1.0 ships no linux-x64 prebuild), so it is the one that must be
rebuilt deliberately:

- Rebuild it in the Debian 12 chroot (`/var/lib/dsh-pty-build` on the dev
  host) with the official Node v24.19.0 tarball — never with a distro's
  `nodejs` package (its node-gyp links `libnode.so.*`) and never on the
  build host itself.
- Verify before packaging: `objdump -T` max ≤ `GLIBC_2.34`, no `libnode`
  NEEDED entry, and the bundled Node imports it.
- CI enforces this: `build-node-pty` compiles in a `debian:12` container and
  both Linux package jobs override `node_modules` with that artifact;
  `after-pack.js` rejects any `pty.node` exceeding the baseline.

## Verification

Before considering a packaging change complete:

1. Run `npm test`.
2. Run `git diff --check`.
3. Build the affected target.
4. Launch the unpacked application with a clean temporary `HOME`.
5. Confirm the Web UI reaches HTTP 200.
6. Verify bundled Node and npm versions.
7. Import the memory plugin, Jieba, and sqlite-vec from the packed tree.
8. Run `ldd` on Electron, bundled Node, and native modules on Linux; no
   dependency may report `not found`.
9. Run the glibc scan on all bundled native payloads
   (`objdump -T <file> | grep -o 'GLIBC_[0-9.]*' | sort -V | tail -1`);
   nothing may exceed `GLIBC_2.34` (the support-matrix baseline, see
   `docs/support-matrix.md`). In particular `node-pty`'s `pty.node` must be
   rebuilt in a low-glibc chroot (Debian 12 + official Node), never compiled
   on the build host, or Debian 13 and older systems crash at launch.
10. Inspect the pacman archive for `.PKGINFO`, `.MTREE`, `.INSTALL`, desktop
    entry, icon, executable, and bundled runtime files.

The known-good Arch Linux v3.0.1 artifact is
`dsh-desktop/dist/Deepseek-Harness-EAC-3.0.1-x64.pacman` (SHA-256 is recorded
after the first verified v3.0.1 build; the rebuilt artifact with the glibc-2.34
`pty.node` supersedes the original).

## Change Discipline

- Preserve bundled third-party licenses and notices.
- Do not commit `dist/`, `vendor/`, logs, caches, or temporary audit extracts.
- Avoid unrelated formatting or dependency churn.
- Update `README.md` whenever supported platforms, package names, build
  commands, runtime versions, or installation steps change.
