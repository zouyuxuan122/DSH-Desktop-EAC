## 1. 问题确认（本轮的「检查问题存不存在」结论）

1. **内核无罪**：`@deepseek-ai/dsh-tool-pwsh` 的 `required` 恒为 `['command','description']`，`sandbox_permissions`/`justification` 仅在存在可升级目标（受限默认模式）时才被告示；`llm-deepseek/serialize` 对 `parameters` 原样透传，无任何重建 required 的层。
2. **错在接收方**：部分外部 OpenAI 兼容网关/适配器忽略 `required` 数组。内核无法修复第三方网关，故 EAC 侧锚点补丁（patch-deps）是最小正确解：默认 `danger-full-access` 时**不告示**这对字段（没有可升级目标，告示即必然失败）；`workspace-write` 等较窄策略下照常告示，**动态升级能力保留**。
3. **管线缺口（本轮核心发现）**：Tauri 打包 `stage-resources.mjs` 在 staged 目录 `npm ci --omit=dev` 从 registry 全新装 node_modules，而 `patch-deps.js` 不在 SCRIPTS 清单、staged 内无任何步骤运行它 → **重建也带不上补丁**。`package.json` 里 pack/dist 挂的 patch-deps 是已冻结 Electron 路径，对 Tauri 产物无效。修复提交（18b0fd40）恰晚于 v5.1.0 构建，故 dev/release/已安装 App 三处此前全是未打补丁旧代码（已逐一核实零标记）。
4. 行为验证（临时脚本，stub ctx 调 `apply()`，跑完即删）：
   - `danger-full-access`：schema 无 `sandbox_permissions`/`justification`，required 不变；
   - `workspace-write`：两字段在，enum `['workspace-write','danger-full-access']`；
   - 无沙箱执行器：两字段不在。

## 3. 环境陷阱（本轮新踩，下轮必读）

1. **C 盘常年 100%**：本轮一度仅剩 292M，NSIS 经 %TEMP% 中转必败（R7 §3.2 同款）。处理：清 `%TEMP%\_MEI*`（PyInstaller 残留，本轮清掉 369M）；构建时 `export TMP/TEMP=D:/.../.build-tmp` 把瞬时文件引到 D 盘。**构建/安装前先 `df -h /c`。**
2. **Git Bash 的 `/S` 会被 MSYS 路径转换改写**（`/S` → `C:/Program Files/Git/S` 之类），导致 NSIS 安装器以交互模式启动、停在安装窗口等人点按钮（进程驻留、目录零变化）。静默安装必须 `MSYS_NO_PATHCONV=1 ./xxx-setup.exe /S` 或经 `cmd //c` 正确引号。
3. **WebFetch 在本机撞证书**（UNABLE_TO_VERIFY_LEAF_SIGNATURE）；GitHub 连接用 `curl --ssl-no-revoke` 或 `git -c http.sslVerify=false fetch`（本轮 git fetch 未撞，直接用即可）。
4. **Compress-Archive 便携包内部路径用反斜杠**：`unzip -l/-p` 的正斜杠 pattern 匹配不到，且 unzip 把 `\` 当转义符 → 验证便携包内容用 PowerShell `ZipFile` 按精确条目名读，或搜条目名不含 `lib\index.js` 时用 `grep 'lib.index'` 之类。本轮便携包内两个内核文件标记已用 PowerShell 确认为 1。
5. **bundle 目录遗留 `Deepseek Harness EAC_5.0.0_x64-setup.exe`**（R7 §6.4 提醒过）：发版前删掉防误传。

作者静态核对 + 内核核实一致：**完全访问分支无文件后端 bug**（fs-sandbox 157-161 / bash-sandbox 143-153 / pwsh-sandbox 151-161 / terminal-bash 729-737 全部绕过 containment，逻辑正确）。真凶候选两个：
