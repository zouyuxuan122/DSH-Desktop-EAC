## 1. 发布阻断 bug 三处（安装态冒烟实测抓出，已修复+回归）

### 1.1 stage-resources 漏装配 → sidecar 启动即崩（最严重）
`lib/desktop/companion-sync.js` require `../plugin-copy.js`，`lib/extension-host/rpc.js`
require `../../shared/protocol.js` —— 两个模块都不在 stage-resources 装配清单里。
发布树缺文件 → 安装态 sidecar 一启动就 MODULE_NOT_FOUND（dev 态不暴露：repo 有完整源文件，
staged 是过滤拷贝）。
修复：`stage-resources.mjs` 的 LIB_VNEXT 加 `plugin-copy.js`，另加 `shared/protocol.js` 拷贝行。
**防回归手段**：stage 完成后对 staged 树做「相对 require 全解析扫描」（见下），当前已零缺失。

### 1.2 恢复中心直开模式 serve_ws 缺失 → 窗口/桥不可达
main.rs 恢复分支（DSH_DESKTOP_RECOVERY=1）在 `serve_ws(...)` **之前** return —— 恢复中心页
（http_serve /recovery-center）与 rc.preload 的 WS 桥全挂在 19873 同端口服务上，漏起则窗口白屏、
rc.* 全部不可达。修复：恢复分支内补 `serve_ws(st, app_handle).await;` 再 return。
G2 Phase C 已验证：恢复模式 WS 桥连通、恢复中心页 200、rc.action status ok、零孤儿。

### 1.3 Extension Host 残留 running 态 → 插件永不拉起
sidecar 异常终止（被杀/断电/崩溃）时插件正处 running，注册表留下 stale 标记；`startEnabled()`
只拉 `installed/failed/retrying`，且状态机拒绝 `running→starting` → 该插件从此静默不启动。
修复：`manager.startPlugin` 顶部（内存防双启守卫后）对 `running` 态应用 `crash` 事件对账
（running→retrying/quarantined，自动退避，复用既有机制）。
回归测试：`残留 running 态 → 崩溃对账 → 自动重启恢复`（654/654 全绿）。

## 3. 用户实测问题分析（根因 = 环境，非代码）

用户运行安装版遇到：① 内测声明点继续报「暂时无法保存确认状态」；② 弹「浏览器窗口」
（地址 http://127.0.0.1:55339/，用户认为是豆包浏览器）；③ 插件加载慢 + 「Failed to load
plugins」（dsh-balance bundle 404）。

### 3.1 内测声明保存失败
内测声明＝内核欢迎声明（`@deepseek-ai/dsh-client-ui-settings-models`，WELCOME_NOTICE_VERSION
2026-08-13.1），确认写 `<harness home>/settings.yaml`（`ui-onboarding.welcomeNoticeVersion`）。
落盘走 `@deepseek-ai/dsh-atomic-write`：**同目录临时文件 + rename**。真实 home 在 C 盘，
C 盘长期 100% 满（会话期间 514M–1.4G 波动）→ ENOSPC → 写失败 → 弹「暂时无法保存确认状态」。
**已处理**：清理 `C:\Users\HUAWEI\AppData\Local\Temp`（2.2G→135M，含 _MEI 残留），C 盘回升到 2.2G 可用。
注：真实 home 的确认记录 8-23 22:17 已写入（版本匹配），正常情况不弹声明；用户遇到弹窗的场景
是磁盘满时的写失败路径。

### 3.2 「弹浏览器窗口」
**结论：应用不会打开系统浏览器（豆包/Edge）**。160 秒完整启动观测：0 个外部浏览器进程带
55339。用户看到的 `http://127.0.0.1:55339/` 窗口是**应用自身的主窗**——无边框 WebView2
（Chromium）窗口渲染 dsh web UI，视觉上就是浏览器页面。Web UI 全量 grep：无 `window.open`，
`target="_blank"` 仅用于外链点击（设置/关于页），点击才会开默认浏览器，属预期行为。

### 3.3 插件加载失败（dsh-balance 404）
真实 home 的 profile（`~/.dsh/profiles/web-desktop`）是 Electron 时代的旧树，Tauri 首跑要
重新同步（companion-sync 拷贝 46 个插件）；C 盘满+慢导致同步期间 bundle 读取与拷贝竞态 →
`/plugins/@deepseek-ai/dsh-balance/client.js` 短暂 404 → 内核启动屏显示 Failed to load
plugins。**fresh home 实测全部 200**（`lib/client.js` 经 exports 映射正常服务）。同步完成后
真实 home 也已恢复 200。非 Tauri 回归，属旧 profile 迁移 + 磁盘满的瞬时竞态。

## 4. 环境备忘（新增/更新）

- **C 盘是最大环境风险**：Temp 曾 2.2G/_MEI 残留；WebView2 用户数据也落 C 盘。启动应用前
  建议 `df -h /c` 检查；再满优先清 `AppData\Local\Temp`。
- Git Bash 直接跑 NSIS 安装器 `/D=` 会被吞（回退默认 $INSTDIR）——用 PowerShell 传参
  （`& 'setup.exe' /S /D=D:\path`）。`/LOG=` 必须放 `/D=` 之前。
- NSIS 解压 34k 文件约 40–60s 且 setup 进程先退出——验证要轮询完整关键文件集，不能只看 exe。
- tauri build 对 target/release 的 resources 是**合并复制**：staged 删除的文件会在旧树残留，
  需要时手动清（本轮 main.js/preload.js 即此例）。
- 安装态调试：release 壳把 sidecar stderr 丢弃（Stdio::null），sidecar 日志看不到；可用
  `node sidecar/server.js` 手动驱动（DSH_RESOURCE_ROOT/DSH_HOME 注入）复现崩溃。
- WebView2 CDP：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223"` +
  playwright connectOverCDP 可驱动主窗 UI（本轮用此复现 welcome/插件加载）。

## 7. R12 追记（2026-08-24 晚）：3.2「弹浏览器」结论修正 + 两处修复

### 7.1 修正：内核确实会在每次启动时打开系统浏览器（3.2 为误判）

R11 的 160 秒观测漏掉了服务端交接。实锤证据（userData 日志
`AppData/Roaming/Deepseek Harness EAC/logs/dsh-web.log`）：

- `dsh web: opening the default browser; pass --no-open to disable` 共 **50 次**，
  与启动次数一一对应；`could not open the default browser`（失败回退）**0 次**
  —— 每次都成功把 `http://127.0.0.1:<port>` 交给了系统默认浏览器。

根因链：内核插件 `@deepseek-ai/dsh-web-app` 的 Config `openBrowser` 默认 `true`
（lib/index.js），bundle patch 里 web-runtime 行取自命令行
（`!!js ctx.webStartup.openBrowser`）；壳此前从未传 `--no-open`，于是 dsh web 就绪后
用内置 node 跑 `open` 包 → 打开默认浏览器渲染壳自己的端口页面。用户看到的
「豆包浏览器窗口 = 套壳端口」即此，并非 R11 所述「应用自身无边框 WebView2 主窗」。

修复（红线内，只动封装层启动参数）：两处 dsh web spawn 参数加 `--no-open`：

- `dsh-desktop/main.js`（Electron 轨 startServer）
- `dsh-desktop/lib/desktop/boot-server.ts/.js`（Tauri sidecar 轨 boot-server）

profile 层无冲突（`.dsh/profiles/web-desktop/cordis.patch.yml` 只 insert 不覆盖
web-runtime 行）。回归：654/654 绿；boot-smoke 全程 opening 计数不变；
安装态冒烟（NSIS 静默装到 D:\DSH\tmp\g2-install-test → 启动）HTTP 200、
窗口标题正常、opening 计数全程不变、win.close-force 优雅退出零孤儿。

### 7.2 修复：stage-resources.mjs 的 --skip-npm 是死代码

原实现第 104 行无条件 `rmSync(staged)` 整树清空，随后第 161 行才
`existsSync(node_modules)` 判定 → 判定对象必不存在，--skip-npm 永远不生效。
已改为清空前判定并对 node_modules 豁免删除（保留上次 npm ci 生产树），
本轮打包实测生效（跳过 ci、patch-deps 重放与 vendored 回填照常执行）。
