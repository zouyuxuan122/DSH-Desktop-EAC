# 桌面快捷方式唯一性修复设计

## 背景

Windows 会把当前用户桌面和公共桌面合并显示。当前安装流程存在两个快捷方式创建者：

- NSIS 安装器根据 `electron-builder.yml` 创建安装版快捷方式；
- 应用启动时的 `maintainShortcuts()` 在当前用户桌面创建并维护快捷方式。

当 NSIS 把快捷方式写入公共桌面时，`maintainShortcuts()` 只扫描当前用户桌面，无法识别已经存在的公共桌面快捷方式，于是再次创建同名快捷方式。用户最终会在桌面看到两个都指向本应用的图标。

## 目标

- 全新安装后，软件自身最多创建一个桌面快捷方式。
- 安装版由安装器负责创建桌面快捷方式。
- 便携版在没有软件快捷方式时创建一个当前用户桌面快捷方式。
- 升级现有版本时，安全清理由软件生成且未经用户修改的重复快捷方式。
- 用户自行复制、改名、更换图标或修改属性的快捷方式不得被删除或覆盖。
- 开始菜单快捷方式的现有维护行为保持不变。

## 非目标

- 不强制删除用户主动创建的多个快捷方式。
- 不修改用户自定义快捷方式的名称、图标、参数或描述。
- 不改变安装向导中的“创建桌面快捷方式”选择。
- 不扩大到 macOS 或 Linux 的快捷方式行为。

## 方案选择

采用“按发布形态划分唯一创建者”的方案：

- NSIS 安装版：安装器是桌面快捷方式的唯一创建者。
- 便携版：运行时 `maintainShortcuts()` 是桌面快捷方式的唯一创建者。

未采用以下方案：

- 完全关闭安装器创建：卸载清理和安装向导选项会失去统一管理。
- 仅增加公共桌面扫描：只能阻止新重复，无法清理已经由旧版本生成的重复项。
- 删除所有指向本应用的多余快捷方式：可能误删用户自行复制或修改的快捷方式。

## 快捷方式目录

Windows 下检查两个位置：

1. 当前用户桌面：`app.getPath('desktop')`
2. 公共桌面：优先使用 `%PUBLIC%\Desktop`

目录列表需要去重，并允许公共桌面不存在或不可访问。读取失败只能记录日志，不能阻止应用启动。

## 快捷方式识别

识别分为两层，禁止用同一套严格条件同时承担“阻止创建”和“允许删除”：

### 已有应用快捷方式

任意名称的 `.lnk` 只要 `target` 指向当前应用 exe，就视为桌面上已经存在应用快捷方式。它可以阻止运行时再次创建，但不代表程序有权删除它。

这样用户改名、换图标或复制快捷方式后，程序不会因为标准文件名消失而重新创建第二个。

### 可自动删除的软件生成快捷方式

快捷方式只有满足以下全部条件时，才可被视为软件生成并参与自动删除：

- 文件名为标准名称 `Deepseek Harness EAC.lnk`；
- `target` 指向当前应用 exe，或在 exe 搬迁场景下指向设置中记录的上一个应用 exe；
- 属性符合已知生成器之一：
  - 运行时生成：描述为 `DeepSeek Harness 桌面客户端`，图标为空或指向应用维护的 `icon.ico`；
  - 安装器生成：描述为发行配置中的标准描述，图标为空或指向应用 exe。

如果名称、描述、图标、参数或目标无法匹配已知生成器，则视为用户资产，不自动删除。

自动清理还必须同时识别到“安装器生成”和“运行时生成”两种来源。两份完全相同的安装器快捷方式或运行时快捷方式无法与用户手动复制可靠区分，因此宁可保留，不做自动删除。

安装版与便携版通过 electron-builder 提供的 `PORTABLE_EXECUTABLE_FILE` 环境变量区分；存在该变量时按便携版处理，否则按安装版处理。

## 行为流程

### 安装版

1. NSIS 按安装向导选项创建一个桌面快捷方式。
2. 应用启动后扫描当前用户桌面和公共桌面。
3. 运行时不再为安装版补建桌面快捷方式。
4. 如果同时存在安装器生成和运行时生成的标准快捷方式：
   - 保留安装器生成的快捷方式；
   - 只删除可明确识别为运行时生成、且未经用户修改的重复项。
5. 如果用户在安装时取消创建桌面快捷方式，应用启动后不得重新创建。

### 便携版

1. 启动时扫描当前用户桌面和公共桌面。
2. 没有任何指向当前便携版 exe 的快捷方式时，在当前用户桌面创建一个。
3. 已存在任意名称、任意图标且指向当前便携版 exe 的快捷方式时，不再创建。
4. 如果旧版本留下两个可明确识别的软件生成快捷方式，保留指向当前便携版 exe 的当前用户桌面快捷方式，删除另一份软件生成的重复项。
5. 用户修改或复制的快捷方式不参与自动删除。

### 升级迁移

去重逻辑在启动时幂等执行：

- 第一次启动可删除旧版本留下的软件生成重复项；
- 后续启动在只有一个快捷方式时不产生写操作；
- 删除失败只记录日志，不弹阻塞窗口，也不继续创建第三个快捷方式；
- 不需要额外永久迁移标记，实际文件状态即为幂等依据。

## 代码组织

将桌面快捷方式判定拆为可测试的小函数，避免继续增加 `maintainShortcuts()` 的复杂度：

- `desktopShortcutDirs()`：返回当前用户桌面和公共桌面。
- `shortcutTargetsApp()`：仅判断快捷方式是否指向当前应用，用于阻止重复创建。
- `classifyManagedShortcut()`：严格分类为安装器生成、运行时生成或用户资产，用于决定是否允许删除。
- `dedupeManagedDesktopShortcuts()`：根据安装版或便携版保留唯一的软件生成快捷方式。
- `maintainShortcuts()`：保留流程编排、开始菜单维护和必要日志。

如果拆分独立模块会引入 Electron `shell` 注入复杂度，可先保持在 `main.js`，但判定函数必须是纯逻辑或接受依赖参数，以便测试。

## 错误处理

- 公共桌面不可读：跳过该目录并记录日志。
- 快捷方式损坏或无法解析：视为未知文件，不删除。
- 删除快捷方式权限不足：记录路径和错误，不影响应用启动。
- 安装版检测到公共桌面快捷方式后，即使无法删除个人桌面重复项，也不得再次创建。
- 任何不确定归属的快捷方式都按用户资产处理。

## 测试

至少覆盖：

1. 全新当前用户安装：桌面只有一个安装器快捷方式。
2. 全新全用户安装：公共桌面只有一个安装器快捷方式，运行时不在个人桌面补建。
3. 安装向导取消桌面快捷方式：首次启动后仍然没有桌面快捷方式。
4. 便携版首次启动：个人桌面创建一个快捷方式。
5. 便携版再次启动：不重复创建。
6. 旧版本留下个人桌面运行时快捷方式，同时安装器创建公共桌面快捷方式：删除运行时生成项，保留安装器生成项。
7. 用户改名快捷方式：不删除、不重建标准快捷方式。
8. 用户更换图标：不删除、不覆盖图标。
9. 用户自行复制快捷方式：不自动删除用户副本。
10. 公共桌面读取或删除失败：应用正常启动且不创建第三份快捷方式。

## 验收标准

- 在干净 Windows 环境安装并首次启动后，软件自动创建的桌面快捷方式数量为一个。
- 从存在两个旧版官方快捷方式的环境升级后，只剩一个官方快捷方式。
- 用户改名、换图标或复制的快捷方式保持原样。
- 安装时取消创建快捷方式后，应用不会违背用户选择重新创建。
- 安装版、全用户安装和便携版路径均有自动化测试或可重复的发布验收步骤。
