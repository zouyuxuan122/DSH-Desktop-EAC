## 2. 关键发现（破案记录，下个模型必读）

### 2.1 §5.1「布局之谜」破案（Stage 1，已完成）
- **真相**：Tauri v2 的 `bundle.resources` map 目标相对安装根，NSIS 装出 `exe 同级 sidecar/ + dsh-desktop/` 兄弟目录，**没有 `resources/` 这一层**。上一轮看到「app/node/npm」布局，是因为 `%LOCALAPPDATA%\Programs\Deepseek Harness EAC` 被**旧 Electron 安装**占据（同名目录测量假象）。
- **修复**：`resource_root()` 三级探测（见 §1）。**结论：tauri.conf.json 的 resources map 无需改成数组**。

### 2.2 makensis `mmap` 失败根因 = C 盘空间耗尽（Stage 3 途中，关键！）
- R5 说「重试即可」（build5 失败 build6 成功），但**真正根因是 C 盘只剩 0.1GB**，而 `%TEMP%` 在 C 盘。32 位 makensis 压缩 500MB 包需要 mmap ~148MB 提交空间 + 临时文件，C 盘耗尽即 `Internal compiler error #12345: error creating mmap`。
- **解法**：把 `TEMP`/`TMP` 重定向到 D 盘后**立即成功**：
  ```powershell
  New-Item -ItemType Directory -Force -Path "D:\Temp\nsis-temp" | Out-Null
  $env:TEMP = "D:\Temp\nsis-temp"; $env:TMP = "D:\Temp\nsis-temp"
  & "C:\Users\HUAWEI\AppData\Local\tauri\NSIS\makensis.exe" installer.nsi
  ```
- 也可直接对 `target\release\nsis\x64\installer.nsi` 单独重跑 makensis（跳过 Rust 重编译），但**注意**：直接跑 makensis 不带 `-DOUTFILE=...` 会输出 `nsis-output.exe`，需手动复制到 `bundle\nsis\Deepseek Harness EAC_5.0.0_x64-setup.exe`。

### 2.3 AV 干扰导致 NSIS 安装器解压随机中断（Stage 1/3，环境阻塞）
- **现象**：静默安装 `exit 2`，安装树文件数随机（3 次 3 个不同中断点：约 27% / 75% / 98%），卸载键未写、快捷方式未建。这是 AV 实时扫描放大导致 500MB 解压中断，**不是代码 bug**（staged-resources 与 target/release 布局都正确）。
- **workaround**：用 `robocopy /MIR` 把 `staged-resources`（或 `target\release\{sidecar,dsh-desktop}`）补齐成完整安装树，等价验证安装形态（本轮的「安装形态 GUI 冒烟 18/18」即用此法）。

### 2.4 electron-builder 卸载键名 = productName（Stage 3，已完成）
- R5 的 `installer-hooks.nsh` 只探测 `com.deepseek.dsh.desktop`（identifier），但**真实旧 Electron 壳的卸载键名是 productName「Deepseek Harness EAC」**。已改为双候选键探测。
- **脏值防御（新增）**：本机实测旧键的 `UninstallString` 指向已删除的 `D:\Deepseek Harness EACeac\uninstall.exe`（脏值），若直接 `ExecWait` 会卡死静默安装。已加 `${FileExists}` 判存，缺失时跳过 ExecWait 只 `DeleteRegKey`。

### 2.5 ExecWait「疑似被 AV 拦截」→ 定案为双引号代码缺陷（收尾轮已修复，bd4244d7）
- 收尾轮用 mock 卸载器（csc 编译、退出码 42、写标记）+ 最小安装器 A/B 对照定案：
  - T1 无引号键值 → spawn 正常；T2 带引号键值（electron-builder/Tauri 模板真实形态）→ **spawn 静默失败**。真凶：`ExecWait '"$0" ...'` 内嵌**未剥引号的原始值 $0**，展开成 `""path"` 嵌套。
  - 追踪版进一步揪出次生缺陷：`_?="$1"` 带引号时 NSIS 卸载器**原样取命令行剩余串当目录**，字面 `"` 混入路径 → 退出码 2、零删除；也正因原样取剩余，**含空格目录裸写即安全**（官方文档示例 `_?=$INSTDIR`）。
- **修复**：程序路径改用剥过引号的 `$3` + `_?=` 裸写 `$1`（保留尾反斜杠剥离防御）。三级验证全绿：最小安装器 6 用例矩阵 → 追踪版 A/B → 真实 Setup `/S` 端到端（旧 NSIS 卸载器被完整接管 38599→1、mock 标记写入、双键清理、新装全量解压）。
- 上轮「退出码变量未被覆盖」的怪象即缺陷表现之一，非 AV 拦截。AV 干扰结论仅保留给 makensis mmap（#24 的 C 盘空间才是主因）与历史 hook 测试现象。

### 2.6 其它小发现
- `gui-smoke.js` 第 124 行 getInfo 断言曾硬编码 `4.6.0`，已改动态读 package.json。
