## 2. 架构现状（比第四轮多了什么）

三层架构不变：**Rust L1（tauri-shell/src/main.rs）↔ Node L2 sidecar（tauri-shell/sidecar/server.ts）↔ dsh 内核 L3（零改动）**。本轮新增：

### 2.1 L1 Rust（main.rs，~1100 行）
- **启动序列**：spawn sidecar → 绑定 `127.0.0.1:19873`（HTTP + WS 同端口）→ 主窗先加载 `/loading` → `boot.start` → webUrl 回传 → 导航真实 Web UI。
- **壳层方法拦截**（WS 中继处本地处理，不转发 sidecar）：`win.minimize/toggle-maximize/close/is-maximized/start-dragging`、`float.open/close/ready`、`menu.action` 的纯壳动作（reload/devtools/fullscreen/quit/open-browser/feedback）、`shell.open-external`、`recovery.restart`、`log.*`（send 型）。
- **通知广播**：sidecar 通知（`boot.web-ready`/`boot.server-died`/`boot.failed`/`dsh.balance`）+ 壳层通知（`win.maximized`/`float.ready`）都经 `broadcast` 推给 WS 连接。
- **浮窗**：`float.open` → `WebviewWindowBuilder` + 独立 `data_directory`（`app_data_dir()/float-webview`）= 硬门槛①。浮窗 init 脚本注入 `window.__DSH_FLOAT__ = {sessionId, win}` 并发 `float.ready`。
- **退出策略**：`CloseRequested` → `apply_exit_policy`（minimize→隐藏 / quit→exit / ask→`/exit` 三选页 + 记住选择）；`ExitRequested` 同步有界关停 sidecar（shutdown RPC → stopServer → kill）。
- **打包态资源根**：`resource_root()` = exe 同级 `resources/sidecar/server.js` 存在则用它，否则回退开发布局（`CARGO_MANIFEST_DIR/..` 的 canonicalize）。**这是 §5 待核对项的核心**。

### 2.2 L2 sidecar（server.ts ~700 行 + rescue-integration.ts ~380 行 + boot-server.ts ~280 行）
- **挂载 14 个 L2 模块**：proc / runtime-paths / profile / guard-box / runtime-patches / companion-sync / plugin-ops / market / shortcuts / junction-patrol / client-update / static-preview / file-roots / **boot-server**。
- **`boot.start`**：完整前置准备（市场排队 → 退役清理 → 配套插件/技能同步 → 模块遮蔽修复 → 产物回填）→ spawn dsh web（稳定端口/受限端口重试/HTTP 探针竞争/首启 180s）→ `{webUrl, port}` → `boot.web-ready` 通知 → 启动 15min 余额轮询。
- **`boot.restart`**：无锁窗口内重装模块树后拉起（= Electron restartWebServiceCore）。
- **真实现桥方法面**：`chrome.init`（getInfo 真实组装）、`balance.*` 全家族、`clipboard.write-text`（PowerShell）、`files.revert/open`、`image-paste.save`、`plugins.*`、`guard.action` 全动作、`menu.action` 开关与 restart-service、`rescue.*`/`safe-mode`/`recovery.*`（rescue-integration.ts）。
- **`.lnk` 驱动**：PowerShell `WScript.Shell` COM，`read`/`write` 同步（路径经 env 传参防转义，IconLocation 剥 `,N` 索引，create/replace 语义，8s 超时）。
- **崩溃循环计数**：`boot.start` 失败 → `recordBootFailureNow`（阈值 3），成功清零；`/died` 页有「安全模式重启」入口。

### 2.3 桥（bridge.ts，编译产物 bridge.js）
按 preload.js 键集逐字节重建 `window.dshDesktop`（~40 方法 + 36px 玻璃栏 + mousedown 拖拽 `start_dragging` + 5s 心跳 + 浮窗模式 + `dsh-balance-changed` 推送）。**键集一致性由契约测试 `bridge-preload-parity.test.mjs` 锁定**（bridge 侧额外键 `_call/_send/_onNotify/_onReady` 属内省，测试已豁免）。

## 4. 环境陷阱（第四轮 §3 全部仍有效 + 本轮新增）

沿用第四轮 §3 的所有条目（cargo 绝对路径 + RUSTUP_HOME/CARGO_HOME、长命令后台化轮询、改码只用 Edit/Write 或 python utf-8 读写、cmd `%ERRORLEVEL%` 陷阱、PowerShell 管道写文件会坏 UTF-8、契约测试路径拆串 grep、注册表脏值防御等）。**本轮新增**：

17. **Git Bash 内联 `node -e` 的反斜杠转义地狱**：多层 shell 引号会把 `\\` 吃成 `\`。写含反斜杠的字符串一律用**文件脚本**或 `String.fromCharCode(92)` 拼，别内联。Rust 里写反斜杠 char 用 `'\u{5C}'`（别用 `'\'` 或 `char::BACKSLASH`）。
18. **tsc commonjs 会把 `await import()` 降级成 `require()`**，require 加载 `.mjs` 会抛「Cannot find module file://…」。动态加载 ESM 一律走 `new Function('specifier','return import(specifier)')`（已修 market.ts 两处；这是 Wave 2 就埋下、本轮才在 sidecar boot 冒烟里暴露的**双壳同享回归**）。
19. **`module.exports =` 在 .ts 里要写成 `export =`**，否则 commonjs 产物导出形态不对；根模块转 .ts 后必须加 `.js` 到 `dsh-desktop/.gitignore`（tauri-shell 的产物加 `tauri-shell/.gitignore`，两个 gitignore 是分开的）。
20. **根 .ts 模块必须至少一个 import/export**，否则 tsc 当全局 script 处理，多个文件同名变量（fs/path）互相 redeclare。
21. **`git add -A` 会把 `tmp-p2boot/`（冒烟临时 DSH_HOME，含几千个 node_modules 文件）卷进提交**。冒烟脚本的临时目录在仓库根，已加 `/tmp-p2boot/` 到根 `.gitignore`，但**提交前务必 `git status` 瞄一眼**。
22. **NSIS 打包偶发 `Internal compiler error #12345: error creating mmap`**（32 位 makensis 对大包内存映射，AV 扫描放大触发）——重试即可（本轮 build5 失败、build6 成功）。首次打包 makensis 压缩 518MB 需 ~5-10 分钟，耐心等。
23. **tauri release 需要 `devtools` feature**（菜单 F12 才会在 release 里可用），已在 Cargo.toml 加 `"devtools"`。

## 5. ⚠️ 关键未决项（下个模型第一步就干这个）

### 5.1 NSIS 资源布局核对（最高优先级，阻断交付）
**现象**：`stage-resources.mjs` 产出 `staged-resources/{sidecar,dsh-desktop}` 正确；`tauri.conf.json` 的 `bundle.resources` 映射为 `{"staged-resources/sidecar/":"sidecar/", "staged-resources/dsh-desktop/":"dsh-desktop/"}`；cargo 构建后 `target/release/{sidecar,dsh-desktop}` 兄弟目录也存在且内容正确。**但**第一份 NSIS 安装出的 `%LOCALAPPDATA%\Programs\Deepseek Harness EAC\resources\` 下是 `app/ node/ npm/`（dsh-desktop→app、vendor/node→node、vendor/npm→npm），**且 sidecar 三件套（server.js/bridge.js/rescue-integration.js）根本没进包**。

**待做**：
1. 等 build7（`npx @tauri-apps/cli@2 build` 已在后台，日志 `tauri-build7.log`）跑完，**静默安装**到干净目录（注意：Git Bash 里 `/D=...` 会被 MSYS 路径转换吃坏，用 `MSYS_NO_PATHCONV=1` 或用无空格绝对路径），**逐项核对安装树**。
2. 若仍缺 sidecar：优先排查 tauri v2 的 `bundle.resources` map 语义（dir 源是否要带尾斜杠、目标是否相对 resources/），必要时改成 **数组形式显式列文件**（`["staged-resources/sidecar/server.js", "staged-resources/sidecar/bridge.js", …]` 或 glob），宁可啰嗦也要确定。
3. **让 `main.rs::resource_root()` 与实测布局一致**。当前它只认 `exe_dir/resources/sidecar/server.js` 或开发布局 `CARGO_MANIFEST_DIR/..`；如果 NSIS 实际是 `resources/sidecar`，保持即可；若 Tauri 强制把 app 树放到 `resources/app`、node 到 `resources/node`，则同步改 `resolve_node()`/`dsh_desktop_dir()`/`server.ts` 的 `DSH_DESKTOP_ROOT` 解析，并让 sidecar 三件套落到能被 `resource_root()` 找到的位置（必要时在 stage-resources 里把 sidecar 直接塞进 dsh-desktop 树里，避免和 Tauri 的 app/node 命名冲突）。
4. 验证点：**装完直接双击 exe（不设 DSH_HOME），能起真实 dsh web 且桥可用**，即打包态路径解析闭环。

### 5.2 自更新（硬门槛③）+ 老版升级（核心交付）
- `client-update.ts`（lib/desktop）已在 sidecar 挂载，但 GUI 侧还是 stub：`showUpdateWindow:()=>null`、`prepareQuitForClientUpdate` 只打印。**要接线**：`menu.action('check-client-update'/'check-agent-update')` 与自动更新定时器 → `runClientUpdateFlow`；进度经 `notify('client-update.progress', …)` 推桥，`/update` 页（复用 `/died` 页那套壳层 HTTP 路由）展示进度。
- **便携版自更新**是全新场景：Tauri 没有单 exe 便携，是「exe + resources 目录树」。现有 client-updater 的便携 apply = 单 exe 原地替换，需改成「下载新 zip → 解压 staging → 目录树 swap → relaunch」。安装版（NSIS）路径沿用现有 PowerShell + Setup `/S`。
